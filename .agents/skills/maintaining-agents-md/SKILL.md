# Maintaining AGENTS.md & Agent-Ready Codebases

## Overview

An `AGENTS.md` file customizes how AI coding agents perceive and interact with a repository. Based on Matt Pocock's [Set Up Your Agent](https://www.aihero.dev/topics/set-up-your-agent) curriculum, this skill establishes a high-performance, token-efficient, and deterministic agent environment using **progressive disclosure**, **deep modules**, and **execution guardrails**.

---

## When to Use

Use this skill when:
- Setting up AI coding guidelines in a new or existing repository.
- An existing `AGENTS.md` or `CLAUDE.md` has grown into an unmaintainable "ball of mud".
- Agents are burning context tokens, hallucinating nonexistent files, or drifting off-task.
- Ensuring cross-agent compatibility across Claude Code, Cursor, Copilot, Antigravity, and Codex.
- Establishing deterministic safety barriers against destructive git or environment commands.

**When NOT to use:**
- Writing general project documentation intended purely for end-user humans (use standard `README.md` or `CONTRIBUTING.md`).
- Documenting temporary or ephemeral debugging notes.

## Quick Reference

| Component | Standard / Best Practice | Anti-Pattern to Avoid |
| :--- | :--- | :--- |
| **Root File** | `AGENTS.md` (< 15 KB, high-signal, progressive disclosure) | 1,000-line "ball of mud" generated by `/init` |
| **Portability** | Symlink `CLAUDE.md -> AGENTS.md` and `agents.md -> AGENTS.md` | Duplicate divergent files across tools |
| **File Paths** | Describe module capabilities & interfaces | Listing granular micro-paths that drift |
| **Plan Mode** | 4-step loop (*Plan $\rightarrow$ Execute $\rightarrow$ Test $\rightarrow$ Commit*); concise plans; unresolved questions checklist | Verbose essay-style plans with no checkpoints |
| **Architecture** | Deep modules with stable public interfaces (*A Philosophy of Software Design*) | Web of shallow interdependent modules |
| **Safety Enforcement**| Deterministic pre-tool hooks (exit code 2 with stderr) | Text prompt pleading ("please don't force push") |

## Step-by-Step Execution Workflow

### 1. Preserve the Instruction Budget
LLMs attend reliably to ~150–300 instructions. Every token in root `AGENTS.md` is loaded on *every turn*:
- **Keep it minimal:** Include only the project role anchor, execution environment, test/lint commands, invariants, and pointers.
- **Progressive Disclosure:** Move language-specific patterns, architecture specifics, and plugin manuals to dedicated sub-documents in `docs/`:
  - `docs/ARCHITECTURE.md`
  - `docs/TESTING.md`
  - `docs/PLUGINS.md`
  - `SECURITY.md`

### 2. Universal Tool Portability (Symlinking)
Ensure single-source-of-truth compatibility across all coding agent platforms:
```bash
ln -sf AGENTS.md CLAUDE.md
ln -sf AGENTS.md agents.md
```

### 3. Enforce the 4-Step Planning Loop
Include these rules in `AGENTS.md`:
```markdown
## Plan Mode Guidelines
- The 4-step loop: **Plan -> Execute -> Test -> Commit**.
- Make plans extremely concise; sacrifice grammar for the sake of concision.
- At the end of each plan, provide a list of unresolved questions to answer, if any.
```

### 4. Deploy Deterministic Guardrails (Don't Rely on Prompt Begging)
Prompt rules like *"Never run git reset --hard"* or *"Always use python inside conda"* fail under pressure. Implement deterministic execution guards:
1. Copy `templates/agent_guard.py` to `scripts/agent_guard.py` and `chmod +x`.
2. Configure `.claude/settings.json` and `.claude/hooks/guard-commands.sh`:
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{ "type": "command", "command": ".claude/hooks/guard-commands.sh" }]
      }
    ]
  }
}
```
When a command violates safety rules, the guard exits with **code 2**, blocking the call and feeding actionable stderr back to the agent.

### 5. Automated Integrity Verification
Add a test in `tests/test_docs_integrity.py` that verifies:
- `AGENTS.md` exists and is under the size/instruction budget (< 15 KB).
- `CLAUDE.md` and `agents.md` exist and resolve to `AGENTS.md`.
- All linked progressive disclosure documents exist and contain valid references.
- `scripts/agent_guard.py` blocks dangerous operations and allows safe ones.

## Common Rationalizations & Red Flags

| Rationalization | Reality | Correction |
| :--- | :--- | :--- |
| *"I should run claude /init to generate the file"* | `/init` dumps bloated, generic boilerplate that drains instruction budget. | Handcraft a lean, progressive-disclosure file. |
| *"Let's list all 200 source files in AGENTS.md"* | File paths drift immediately, poisoning the agent's context. | Document deep modules and public interfaces. |
| *"I'll add another prompt rule telling the agent not to run npm"* | Prompt rules are non-deterministic and burn budget globally. | Use a deterministic `PreToolUse` hook script. |
| *"Plans need to be complete prose essays"* | Long plans bury decisions and waste reading time. | Be extremely concise; end with unresolved questions. |
